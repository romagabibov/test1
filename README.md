# azheritage — интерактивная коллекция костюмов

Исправленная статическая версия на React + Vite. Node.js 20.19+, 22.12+ или 24 LTS.

## Запуск

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Главная страница — каталог с поиском, фильтром региона и типа костюма. Видео открывается после выбора экспоната. Прямые ссылки используют `#/costume/ID`; кнопки браузера «назад» и «вперёд» работают.

## Vercel через GitHub

1. Распакуйте ZIP. Загрузите **содержимое папки проекта** в корень репозитория: `package.json`, `package-lock.json`, `src`, `public`, `index.html`, `vite.config.ts`, `tsconfig.json`, `vercel.json`.
2. Подключите репозиторий к Vercel.
3. Framework Preset: **Vite**. Build Command: **npm run build**. Output Directory: **dist**.
4. Переменные окружения и Gemini API для этой версии не нужны.

`dist/` также содержит готовую сборку для статического хостинга. Для проверки готовой версии:

```bash
npm run build
npm run preview
```

Экспорт полного сайта из студии доступен в собранной / опубликованной версии. При `npm run dev` используйте резервную копию каталога либо сначала выполните сборку и запустите preview.

## Как добавить видео и метки

1. Внизу каталога нажмите **«Студия проекта»**.
2. Выберите экспонат или создайте новый.
3. Загрузите видео: MP4 (желательно H.264), WebM или совместимый MOV. Лимит одного локального файла — 150 МБ. Можно применить прямую HTTPS-ссылку на видео.
4. Плеер сам определяет длительность и размеры. Выберите кадр на временной шкале, нажмите **«Добавить метку»**, затем укажите деталь непосредственно в видео.
5. В разделе «Метки» задайте название, категорию, текст, начало и длительность показа.
6. Для движения метки включите ключевые кадры. На нескольких моментах внутри интервала её показа укажите положение детали; между точками координаты интерполируются.
7. Сохраните экспонат. Метки и текст обновляются в каталоге этого браузера. Предпросмотр открывается кнопкой с глазом.

При добавлении видео обложка создаётся из его кадра. Отдельную обложку можно загрузить вручную. Экспонаты без видео открываются как информационные карточки, без имитации воспроизведения.

## Сохранение, резервные копии и публикация

**Архив не содержит подключённого серверного хранилища или настоящей авторизации администратора.** В исходной версии их тоже не было. Студия работает с локальными черновиками: тексты и настройки хранятся в localStorage, видео и обложки — в IndexedDB. В другом браузере и у других посетителей эти черновики не появляются автоматически. Очистка данных сайта удалит их. Делайте резервные копии.

Для публикации для всех посетителей:

1. Откройте собранный или уже опубликованный сайт.
2. В студии нажмите **«Скачать сайт»**.
3. Полученный `AZHERITAGE_website.zip` содержит сайт, метки, каталог, загруженные видео и обложки.
4. Распакуйте его и загрузите содержимое в отдельный GitHub-репозиторий или замените содержимое репозитория опубликованной версии. Для такого экспортированного архива Vercel: Framework **Other**, Build **npm run build**, Output **dist**. Всё задано в его `vercel.json`.
5. Либо загрузите содержимое `site/` из экспортированного архива на статический хостинг.

Сохраните этот исходный проект отдельно, если планируете менять программный код: экспорт из браузера содержит готовую сборку, а не исходники React. Студия продолжает работать и в экспортированной сборке.

Кнопка **«Резервная копия»** сохраняет переносимый каталог с загруженными файлами. Восстановить его можно через **«Импорт каталога»**. Импорт заменяет локальный каталог; перед заменой появляется подтверждение. Этот же архив можно распаковать: скопировать `catalog.json` и `media/` в `public/` исходного проекта, затем собрать и развернуть проект заново.

Сторонние HTTPS-ссылки при экспорте остаются внешними ссылками. Файлы, загруженные в студии, и встроенный демонстрационный ролик включаются в экспорт. Лимит браузерного ZIP — 400 МБ. Для больших коллекций используйте постоянный видеохостинг; для публикации прямо из админки без деплоя потребуется отдельное серверное хранилище с авторизацией.

## Что исправлено

- Каталог открывается первым; нет автоматического входа в последний активный ролик.
- Удалены повторные загрузки всего видео, массовое декодирование полноразмерных кадров и подмена ролика нарисованной анимацией при ошибке.
- Одна активная перемотка; промежуточные назначения заменяются последним, а очередь восстанавливается даже при пропущенном событии seeked.
- Воспроизведение использует настоящий видеоплеер; автопоказ останавливается при ручном управлении и открытии описания.
- Метки используют время фактического кадра и прямоугольник `object-fit: contain`. Портретные и горизонтальные ролики не обрезаются, координаты совпадают в редакторе и на сайте.
- Исправлена длительность демонстрации: фактически около 10 секунд, а не заявленные в исходнике 15. Встроенный ролик перекодирован с частыми ключевыми кадрами и faststart, хранится в `public/media` и не зависит от сторонней ссылки.
- Описания открываются в доступном модальном окне: Escape, фокус клавиатуры, прокрутка полного текста, закрытие кликом снаружи.
- У меток стабильная нумерация; поддерживаются несколько меток и траектории.
- Загрузка и сохранение явно сообщают об ошибках, неподдерживаемом формате или недостатке места. Временные blob-ссылки не записываются вместо постоянных ссылок на файл.
- Адаптированы каталог, плеер и редактор; прокрутка внутри студии и окон не перехватывается плеером.
- Добавлены переносимые резервные копии и экспорт полной статической версии.

Встроенная коллекция содержит шесть информационных карточек и один демонстрационный видеопоказ. Демонстрационные метки — примеры работы механики. Исторические тексты из исходника сохранены; перед музейной публикацией их должен проверить редактор / специалист.

## Видео для плавной перемотки

Скорость произвольного перехода зависит от кодека, расстояния между ключевыми кадрами, разрешения, устройства и видеохостинга. Для собственных роликов рекомендуется короткий MP4 H.264, 720p/1080p и ключевые кадры каждые 0.25–0.5 секунды. Если установлен FFmpeg:

```bash
ffmpeg -i input.mp4 -c:v libx264 -preset fast -crf 20 -g 6 -keyint_min 6 -sc_threshold 0 -pix_fmt yuv420p -movflags +faststart -c:a aac output.mp4
```

Пример рассчитан на 24 кадра/сек. Для 30 кадров/сек можно использовать `-g 8 -keyint_min 8`. Ссылки на видео должны разрешать воспроизведение и byte-range запросы. Плеер не скачивает заранее все полноразмерные кадры в память и не обещает фиксированную частоту кадров для любого файла.

## Проверки

```bash
npm run build
npm test
```

Тесты проверяют очередь перемотки и её восстановление, последнюю команду после остановки скролла, крайние позиции, геометрию на телефоне, интерполяцию и нормализацию меток, перенос старых ID, безопасность ссылок и сбой сохранения.
